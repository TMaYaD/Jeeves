# FocusSessions never auto-close; day attribution is ES-anchor-based

A FocusSession changes lifecycle state **only by explicit user action**. It opens when the user finishes Daily Planning (Start Day) and closes when the user finishes Evening Shutdown (or the all-done "End Session" fast path). Cadence anchors — the Daily Planning anchor and the Evening Shutdown anchor — are **reminder anchors only**: they decide when a Nudge fires, never when a session opens or closes. There is no code path that closes a session on idle, on a day boundary, or on the next Planning; the previous implicit close inside `openSession` (which silently closed a still-open prior session before opening a new one) is removed, because it destroyed the prior session's un-reviewed Dispositions retroactively.

Because sessions never auto-close, a session is calendar-independent and may span days. **Day attribution is therefore ES-anchor-based, not calendar midnight:** a session belongs to the planning period opened by the most recent Evening Shutdown anchor before its `started_at`. Concretely, a session *qualifies as the current period's* iff `started_at >=` the most recent ES anchor before now (`watchQualifyingSessionExists`). `ended_at` plays no part — a session started after the last ES anchor qualifies whether still open or already closed. This is the single source for "has today's planning happened": a 07:30 plan is after *yesterday's* ES anchor, so it counts as today's; a session open since before the last ES anchor belongs to the previous period, so the Daily Planning nudge re-arms for it while Evening Shutdown wins (the user is guided to close it first). The Now screen still renders any open session as the live session with the Shutdown callout — the qualifying predicate governs nudges and notifications, the open-session fact governs the screen surface.

The **single-open-session invariant is enforced solely by the `openSession` throw** in `FocusSessionDao`: with an open session present, opening another throws `StateError`, and callers gate on it by routing the user through Evening Shutdown first (a sequenced, user-initiated entry, not an auto-launch). No schema-level enforcement exists or can — the production tables are PowerSync views, and a partial unique index on `ended_at IS NULL` cannot be expressed there (the only unique indexes available are on `focus_session_tasks.id` and `todo_tags.id`). The DAO throw is the last line of defence and must not be softened back into an implicit close.

This decision meets the three-criteria filter. It is **hard to reverse**: the banners, the OS-notification reconciliation, the Now screen's planning-done state, and the blocked-start gate all build on "sessions are explicit and ES-anchor-attributed," and reintroducing an auto-close would retroactively destroy un-reviewed Dispositions. It is **surprising without context**: a daily-cadence UI strongly implies day-scoped sessions that roll at the calendar boundary, and a reader would reasonably expect `openSession` to close the previous one. And it is a **real trade-off**: auto-close-at-anchor was the plausible alternative, rejected because sessions are calendar-independent and data-mutating automation must never bypass the user's Review. References ADR-0008 (Cadence as anchor-with-period) and ADR-0016 (off-Plan Disposition storage, whose `rollover` union the "carried over from last session" surface reads).
