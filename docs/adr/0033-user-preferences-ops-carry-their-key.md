# ADR-0033: `user_preferences` ops carry the key that selects their merge strategy

**Status:** Accepted
**Date:** 2026-07-29
**Context:** ADR-0011 (the per-key Conflict Strategy registry), ADR-0030 (every non-LWW strategy is a join-semilattice). Decided at #553 planning and implemented as its Phase-0 slice, #563, from CodeRabbit finding #69 on PR #561.

## Decision

**Every `user_preferences` op that carries `value` also carries the `key` that selects the merge strategy for that field, and the receive path refuses a value-without-key op under `preference_value_without_key`.** Strategy selection therefore reads the op and nothing else. Previously the reducer resolved the selecting key from the op's own fields *or, failing that, from the stored reduced `key` row*, with an unresolvable key falling back to plain LWW — so which lattice arbitrated a value write depended on whether this device had already learned the key, which is to say on arrival order. ADR-0030 makes each strategy commutative, associative and idempotent, but an order-dependent *choice* of strategy breaks order-independence one layer above that: the same two ops could reduce under `max_timestamp_value` on a device that had the key and under LWW on a device that did not, and the two would disagree for ever with nothing marked wrong on either.

The rejected alternative was keeping the fallback and policing the outcome — the shape stays legal, and the stored-key lookup plus an LWW default paper over it. That fallback *was* the order-dependence, and it bought nothing: the shape has no legitimate author. Both writers already carry the key on every value write, and structurally must, because the entity id is `uuid5(workspace_id, key)` — derived *from* the key, so a writer that can address the entity has the key in hand. Refusing the shape thus forecloses it rather than accommodating it. The refusal is a reducer guard rather than a decode-time `malformed_payload` for two reasons: the op parses fine, and the payload codec is a collection-generic format definition mirrored field-for-field in Python, where a `user_preferences`-specific semantic rule would force a mirror the content-blind server never executes. As a guard it lands in the logged-but-refused machinery instead — the envelope is still recorded as chain evidence, `op_log.refused_reason` records which guard fired, and #555's replay honours the recorded verdict rather than re-deciding it. Authoring runs the same guard function before anything is queued, so a future writer that forgot the key fails at its own call site instead of signing an op every peer and its own echo would quarantine.

This supersedes two frozen vectors, `strategy_selection_falls_back_to_lww_without_a_key` and `strategy_selection_reads_the_stored_key`, replaced by `strategy_selection_uses_the_carried_key` and `user_preferences_value_without_key_is_refused` in `spec/sync/reducer_v1_vectors.json`. Retiring a vector is the expensive part of this decision and the reason it is recorded: the guard is fail-closed against pre-existing log data, so any value-without-key op already in a real log would flip from "reduced under some strategy" to "refused" on replay. It ships in the window where that set is provably empty — before the op log holds real data — and after that window the same change would need a migration story rather than a vector swap.
